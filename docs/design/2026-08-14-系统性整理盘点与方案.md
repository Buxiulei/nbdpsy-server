# 系统性整理：现状盘点与收敛方案

- 日期：2026-08-14
- 触发：老板指令「不要让 server 项目都是补丁，需要系统性整理」
- 性质：盘点是事实，方案分三级（结构收敛 / 债务清偿 / 流程止血），按级推进

## 一、现状数字（2026-08-14 实扫）

| 维度 | 数字 | 判断 |
|---|---|---|
| 代码总量 | 43,663 行（app/） | 两周从 0.20 到 0.24.4，**14 天 39 个版本、184 次提交** |
| 最大单文件 | `note_components.py` **5,019 行** | 🔴 一个文件装了引用/合集/活动/封面/标题/正文/图片七种组件编辑 |
| 后台循环组件 | **11 个**（7 调度器 + 2 reaper + 归档 + 即梦） | 🟡 模板相似但各自手写，行为参数分散在 config 30+ 个字段里 |
| 浏览器层错误码 | 仅 note_components 就 **62 个** | 🟡 无注册表，语义靠 grep；本周两次"错误码语义写错误导调用方" |
| 滚动/几何实现 | **8 个文件各有一套** | 🔴 本周三个 bug（侧栏滚轮/锚点失效/卡片区外）全是这族 |
| 设计文档 | 24 份 design + spec | 🟡 无索引、无状态标记（哪些已实现/已过时/待办） |

## 二、补丁堆积的三个根源（不解决根源，整理完还会再堆）

**1. 浏览器几何操作没有统一层。** "hover 到正确容器再滚轮"、"滚动到元素进入某容器可视区"、"点击前确认命中区"这三件事，在 matrix_interact / note_components / audience_collect / note_editing 各写了一遍，每遍带自己的坑。本周三个生产 bug 全是这族的变体，且每次修都只修了当事模块。

**2. 判据与失败语义没有集中定义。** 62 个错误码散在字符串里，"这个失败该重试/该换目标/该转人工"的知识在 reason 文案里，写错一次就误导所有调用方（本周发生两次：`quote_target_not_quotable` 的"重试无用"被人工操作证伪；`select_not_applied` 差点被标成可重试）。

**3. 事故驱动的交付节奏没有留整理档期。** 14 天 39 版全部由需求/事故驱动，每次修复都是"最小改动过全量"，正确但只做加法。

## 三、收敛方案

### A 级 · 结构收敛（改代码，须全量回归，分三批）

**A1 浏览器几何统一层**（最高优先，直接杀掉最大 bug 族）
新建 `app/browser/geometry.py`，收编四个能力：
- `hover_then_wheel(page, human, container_sel)`——滚轮必先 hover 进目标滚动容器（侧栏教训）
- `bring_into_container_view(page, human, el, container_sel)`——元素完整进入**容器可视区**（上下都判，不信 scroll_into_view_if_needed）
- `scroll_until(page, human, container_sel, predicate, *, both_targets=False)`——统一"边滚边找"（支持"两个目标都找到才停"，探针要用）
- `click_verified(page, human, el, verify)`——点后回读验证，未生效收口最内层重试一次
迁移顺序：note_components 引用区（bug 最密）→ matrix_interact → audience_collect → 其余。**每迁一个模块跑一次全量，不整仓一把梭。**

**A2 note_components.py 拆分**（5,019 行 → 按组件域拆七个文件 + 一个共享底座）
`quote.py / collection.py / activity.py / cover.py / text_edit.py / images.py / _shared.py`，对外入口与 REST 契约**零变化**（纯内部移动）。拆完每个文件 ≤900 行，agent 的编辑可靠性和审查粒度都会显著改善。

**A3 调度器基类**（11 个循环组件收敛到一个模板）
`BaseScheduler`：scan 循环 / 可打断 sleep / 单 kind 在飞闸 / idle 原因去重日志 / stop 语义——五件事现在每个调度器手抄一遍。收编后新增调度器只写"挑单逻辑"。

### B 级 · 债务清偿（登记造册，按台账逐项清）

建 `docs/DEBT.md` 债务台账（状态机 open/doing/closed），首批入账：
1. 错误码注册表：码 → 语义 → remediation（retry / retry_via_update_page / change_target / manual / investigating）→ 进 manifest 供调用方机读【本周两次误导的根治】
2. `quote_candidates_unavailable`：弹窗未开族，等新取证（已带自证据）
3. 深位笔记定位（候选窗口 ~50 篇上限）：老笔记引用不可达
4. 发布路径封面 `cover_exception`（更新页可用，发布页待根治）
5. 手工删除不落 `deleted_at`（现靠人工补标）
6. 视频笔记 content/title 编辑开放（已有 20 次读取实证，待写入验证）
7. `_ROW_BAND` 比例判据 vs 固定视口（号6/号7 小视口疑命中，等号7 标本复验）
8. note_ops 文档"标题兜底"过时描述
9. docs/design 24 份加状态头（implemented / superseded / pending）+ 索引

### C 级 · 流程止血（防止继续堆补丁）

1. **每版发布附带"整理税"**：每个 feature 版本至少含一项 B 级台账清偿（本次 0.24.5 起执行）
2. **错误码新增必须过注册表**（写码先写 remediation，写不出=没想清楚——判据自审表纪律落到代码层）
3. **模块行数红线 1,500 行**：超线的文件禁止再直接加功能，先拆再加
