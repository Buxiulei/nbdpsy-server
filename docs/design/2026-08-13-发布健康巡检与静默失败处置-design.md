# 发布健康巡检与静默失败处置（0.25.0）

- 日期：2026-08-13
- 状态：设计稿，待内容运营评审
- 来源：老板需求「每个笔记发布后持续关注审核状态，发布中还是没曝光、别的账号互动不了，就删除重新发布」+「审核通过了才开始触发互动任务，互动不了要及时反馈」
- 实证基础：2026-08-13 全天 RCA（4 篇静默失败处置、A/B 两型分类、李冠阳天然实验）

## 0. 判据自审表（先读这节）

今天所有故障归结为一句：**判据与被判对象之间隔了一层代理**（health 拿"下游依赖可用"代理"调用方进得来"、dedupe 拿"键已落库"代理"消息已送达"、metrics 代理台账、covered 增量代理消化速率、引用 toast 代理可见性）。代理在大多数时候是对的，只在与本体分岔的那一刻失效——而那一刻通常正是出事的时候。

**本设计每个判据都必须在此登记：它代理的是什么、什么可观测条件下会失效、失效时怎么办。**

| 判据 | 真正想知道的 | 代理失效的可观测条件 | 失效时的行为 |
|---|---|---|---|
| **同一页**里对照笔记可见而目标不可见 | 这篇进了公域 | 几乎无代理（同页、同次渲染、同视角，差异只能来自笔记本身）；残余风险=平台对单篇的视角差异 | 两个探针号交叉验证 |
| 对照笔记也不可见 | — | — | 判定**探针号/该主页不可信**，本轮弃权不产出结论 + 告警（这也是李牧阳式半死的最早发现手段） |
| 对照笔记指针仍有效 | 它确证公域可见 | 该篇被删除/转私密/被平台收走后，指针指向一个本就不可见的笔记 | 选取时校验 `deleted_at IS NULL AND permission_code=0`；自证连续失败 M 次先换指针再判半死 |
| 曝光为 0 | 平台没分发 | 新笔记 T+1 前曝光天然为 0 | 只作**T+1 之后**的佐证，绝不当首发信号 |
| 删除返回 not_found | 平台已收走这篇（A 型） | 标题匹配不到 ≠ 笔记不存在（同名/改题） | 仅在**同题卡唯一**时采信；同题多篇走 `ambiguous_title` 拒绝 |
| `permission_code=0` | 这篇是公开的 | **已证伪**：台账与平台真值会漂移 | 不作为可见性判据使用，仅用于 KPI 分母 |
| 引用弹窗 toast | 可引用性 | 不代理可见性（2026-08-13 已证伪） | **不用于健康巡检**，仅用于引用功能自身归因 |
| 推送返回 `ok:true` | 老板收到了 | `dedupe_hit:true` 时未必送达（主后端已知 bug：dedupe 落库早于 audience 解析） | `dedupe_hit:true` 视为**未证实送达**，不计成功 |

## 1. 静默失败的两型（实证分类）

| 型 | 形态 | 判别 | 处置 |
|---|---|---|---|
| **A 型「平台收走」** | 管理页无卡、posted 列表消失 | 删除任务报 `note_not_found` | **免删，直接重发**；not_found 不当失败重试 |
| **B 型「留卡不分发」** | 管理页有卡可删、访客不可见、曝光零 | 删除返回 `deleted=1` | **先发后删**（见 §3） |

探针只能判"访客不可见"，**分不出 A/B**——分型靠删除返回值。样本：号11《凌晨睡不着》= A 型；号1《高警觉》、号8《讨好的本质》《讨好型6信号》= B 型。

**健康笔记的对照指纹**（避免误判，2026-08-13 定标）：互刷 `done/skipped` 且 `not_found=0`、曝光数百以上。真静默失败是互刷 error 14-16 行含 not_found、曝光 0-8。

## 2. 可见性探针（老板「过审才互动」的实现）

### 2.1 流程

**核心设计：同页对照。** 探针打开**目标笔记作者**的主页，在**同一次渲染**里同时找两样东西——待判定的目标笔记，和该作者名下一篇已确证公域可见的**对照笔记**。

```
发布完成 → 延迟 PROBE_DELAY_MIN 分钟 → 探针号 A 打开【作者】主页，同页找两篇：

  对照可见 + 目标可见   → 已进公域 → 放行其余号的全量互动
  对照可见 + 目标不可见 → 目标真的不可见（同页同路径，差异只能来自笔记本身）
                          → 换探针号 B 复探；B 也判不可见 → 记「疑似静默失败」+ 观察队列 + 告警
  对照不可见（无论目标） → 渲染/会话/该主页出问题 → **本轮弃权，不产出任何结论**
                          → 先换对照指针重试一次；仍不可见 → 告警「探针号疑似半死」
```

**为什么必须同页对照，而不是"探针号先自证健康再去看目标"**：李牧阳式半死的症状是「打开**任何发布者主页**都渲染不出笔记卡片」。若对照看的是探针号**自己**的主页/自己的笔记，走的是另一条路径——"自己主页正常、别人主页渲染不出"这种形态完全可能，自证会通过而结论照样错。同页对照把"探针号健康"从**推理**变成**同页比对**，几乎消除代理。

**副产品**：`对照不可见` 这个分支是李牧阳式半死的**最早**发现手段——比 actor 连败熔断更灵敏（后者要撞满 6 次才触发，同页对照第一次就能看出来）。

**探针号 = 首个互动号兼任**，复用现有主页定位逻辑（它本来就会报 `not_found`），零新增浏览器能力，省掉静默失败时其余 7 号的无效会话。

### 2.2 对照笔记指针

每个账号维护一个「对照笔记」指针（该号名下最稳的一篇），存 `xhs_accounts.probe_reference_note_id`。

**选取条件**（三条缺一不可，避免对照本身不可靠）：
1. 发布**已过 T+1**（曝光是 T+1 指标，最近一篇的曝光合法为 0，拿它当对照会让自证误报"半死"，故障从"误判笔记"升级成"探针悄无声息整体停摆"）；
2. 曝光**确实非零**且互刷 `not_found=0`（§1 的健康指纹）；
3. `deleted_at IS NULL AND permission_code=0`。

**指针失效与轮换**（这本身也是个会失效的代理，必须有可观测的换绑条件）：
- 每次使用前校验条件 3；不满足立即换。
- 对照笔记被淘汰引擎删除、被转私密、或自身变成静默失败 → 条件 1/2 复检时自然淘汰。
- **自证连续失败 M 次（默认 2）先换指针重试，再判探针号半死**——否则一个坏掉的对照会把健康的探针号永久判成半死。

### 2.3 确诊与处置门槛

「疑似静默失败」升级为「确诊」需**同时**满足：
- 两个探针号都报不可见（已在 §2.1 内完成）
- **T+1 之后**曝光仍为 0（曝光是 T+1 指标，不可提前采信）

确诊后才进入 §3 的处置。

## 3. 静默失败处置

### 3.1 先发后删（顺序反转，重要）

**机器自动处置一律先发后删**：新篇发布 → 探针确认新篇可见 → 才删旧篇。

理由：李冠阳天然实验证明**旧篇在场不影响新篇分发**（job 68 与 job 77 同内容相隔 4 小时，前者静默死、后者正常分发，且发 77 时 68 的笔记还在）。而先删后发一旦重发卡住（如撞发布冷却），笔记就处于"两头空"——比失败前更糟。人工操作有人盯着可以先删后发，机器不行。

### 3.2 适用范围与终止条件

- **仅对系统发布的笔记自动处置**（有 publish job payload 才拿得到原件）。手工发布的笔记**只告警不自动重发**，显式分支不得静默失败。
- **同一篇内容重发失败 2 次即停止自动重试**，转人工告警。防内容触发的隐性限流把机器拖进死循环（每轮都在烧每号 100 篇的笔记额度）。
- **每次自动删除必须落台账**（不可逆操作没有台账等于没发生过）。

### 3.3 重发前置检查

- **图片体积/格式**：原 payload 若存 PNG 大图（实测 6 张 PNG 共 8.9M 会撞网关），先转 jpg 或复用当时上传成功的图床直链，**绝不原样重放大图**。
- **不带活动挂载**：活动有时效性，过期挂载会毒化发布流。
- 删除走 note_id 定向（现有 `--delete-note` 按标题匹配，同题多篇已由 `ambiguous_title` 硬闸拦住）。

## 4. 告警

### 4.1 A 方案：告警台账（本版自闭环）

新表 `ops_alerts`：`scene / account_id / note_id / title / detail / action_hint / occurred_at / status(open|ack|closed) / dedup_key / created_at`。

- **状态机**：`open → ack → closed`，可标记已处理。**绝不做"每次拉都全量重报"的噪音源**（运营已在别处踩过"把没查到当没有"，不能再造一个反向的噪音坑）。
- **端点**：`GET /api/ops-alerts`（按 status 筛）、`POST /api/ops-alerts/{id}/ack`。
- **coverage 端点响应捎带 `alerts_pending` 摘要块**：运营每天拉完成率时顺手看告警，不用记两个端点。详情与标记走独立端点。
- **一律写账号名称，不写账号编号**（老板明确要求）。

### 4.2 B 方案：微信推送（等主后端端点）

**推送能力在 NBDpsy 主后端，nbdpsy-server 绝不自建**（服务号 access_token 单持有方，两边各刷会互顶）。本服务只做"告警的产生、分级、去重、风暴合并、台账、失败透出"，推送是哑管道。

**契约（照主后端现成端点 `POST /api/internal/wechat-notify/v1/send`，不另造）**：
```
X-Signature: sha256=<hex(hmac_sha256(secret, "{timestamp}\n{raw_body}"))>   ← 必须带 sha256= 前缀
X-Timestamp: <unix 秒，±300s 外报 stale_timestamp>
X-Source:    <调用方标识，落 wechat_notify_logs>
body: { audience: "tag:ops_alerts", content: <200 字以内纯文本>, dedupe_key }
```
- ⛔ **签完不许再动 body 字节**（重新格式化、改缩进、调键序都会让签名失效，且报错是 401 而非"body 变了"）。
- **模板只有单字段 `{{content.DATA}}`，上限 200 字**——告警正文按纯文本组织（账号名 + 标题 + 一句 action_hint，超长截断保留"要你做什么"），**不得按六字段模板组织**。
- **收件人用 `tag:ops_alerts` 标签**，不传 openid 列表（对号池会持续新增绑定，按某一刻快照解析会让告警悄悄长成群发）。
- 返回 `dedupe_hit:true` 视为**未证实送达**，不计成功（见 §0 判据表）。

### 4.3 分级

| 事件 | A 台账 | B 推老板微信 |
|---|---|---|
| 探针判定不可见 | ✅ | 连续 N 次不可见才推（需他 App 核实） |
| K 票 not_found | ✅ | ✖ |
| actor 连败熔断 | ✅ | ✅（需他扫码重登） |
| 自动重发触发 | ✅ | ✖ |
| 二次失败转人工 | ✅ | ✖（运营改内容） |
| **探针号疑似半死** | ✅ | ✅（本版新增，与 actor 熔断同类） |

## 5. 配置（全带默认值）

```
PUBLISH_PROBE_ENABLED: bool = True        # 探针总开关
PROBE_DELAY_MIN: int = 15                 # 发布后多久开探
PROBE_RETRY_INTERVALS: str = "30,120,360" # 观察队列递增间隔（分钟）
AUTO_REPUBLISH_ENABLED: bool = False      # 自动删重发，默认关，实测稳定后再开
AUTO_REPUBLISH_MAX_ATTEMPTS: int = 2      # 同篇重发失败上限，超过转人工
ALERT_PUSH_ENABLED: bool = False          # B 方案总开关，等密钥到位再开
ALERT_INVISIBLE_PUSH_STREAK: int = 3      # 连续几次不可见才推老板
PROBE_REFERENCE_MIN_EXPOSURE: int = 100   # 对照笔记的曝光下限
PROBE_REFERENCE_RETRY: int = 2            # 自证失败几次后先换对照指针再判半死
```

## 6. 测试要求

- **同页对照四分支**：对照可见+目标可见→放行；对照可见+目标不可见→记疑似（经交叉验证）；对照不可见→**弃权不产出结论**（断言此时既不放行也不记疑似）+ 告警。
- **对照指针轮换**：指针指向的笔记被删/转私密时自动换；自证连续失败先换指针再判半死（断言不会因坏对照把健康探针号判死）。
- **对照选取**：拒绝选中未过 T+1 或曝光为 0 的笔记作对照。
- **交叉验证**：单号说不可见不判定；两号都说才记疑似。
- **A/B 分型**：删除报 not_found → 走 A 型免删分支且不计失败；deleted=1 → 走 B 型。
- **先发后删**：断言新篇未确认可见前不发起删除；新篇发布失败时旧篇原样保留。
- **终止条件**：同篇第 2 次重发失败后不再自动重试、落转人工告警。
- **手工笔记分支**：无 publish job payload → 只告警不重发（显式断言不进重发路径）。
- **告警状态机**：ack 后不再出现在 pending 摘要；dedup_key 命中不重复建行。
- **推送契约**：签名串格式、`sha256=` 前缀、200 字截断、`dedupe_hit:true` 不计成功。

## 7. 明确不做（YAGNI）

- 不用引用弹窗当可见性探针（toast 语义是可引用性，2026-08-13 已证伪）。
- 不做创作中心「审核中」状态判定（实测《精神内耗》在创作中心显示正常、访客不可见，该状态不可信）。
- 不在 nbdpsy-server 自建微信推送。
- 不做自动内容改写（内容触发的限流由人改，机器只负责发现与告警）。

## 8. 验收

1. 全套 pytest 绿（显式退出码）。
2. 探针在真号跑一轮，对健康笔记判定可见、对已知静默失败笔记判定不可见。
3. 告警台账端点可查可 ack，coverage 捎带摘要正确。
4. `AUTO_REPUBLISH_ENABLED=False` 时确认不发生任何删除。
5. 判据自审表（§0）每一行在代码里都有对应实现与注释。
